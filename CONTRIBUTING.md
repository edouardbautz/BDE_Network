# Contributing to BDE_Network

Thank you for your interest in this project! This document sums up the general rules. For the detailed setup of a
development environment, see the [contributor guide](docs/en/contributing.md). For the architecture and technical
conventions, see [docs/architecture.md](docs/architecture.md).

## Code of conduct

This project follows a [Code of Conduct](CODE_OF_CONDUCT.md). By taking part, you agree to abide by it.

## Reporting a bug or suggesting a feature

Open a GitHub issue (templates guide you: bug or feature request). For a bug, give the steps to reproduce it, the
expected and the observed behavior, and your environment (OS, Docker version…). For a feature, describe the need
before the technical solution.

## The `main` branch is protected

Nobody pushes directly to `main`, the maintainer included, and no force push is possible. Every change goes through
**a branch and a pull request**, and is only merged when the required continuous integration checks are green:
`ci (ubuntu-latest)`, `ci (windows-latest)`, `docker image`, `migrations` and `docs`.

## Proposing a change

1. Fork the repository and create a branch from `main`.
2. Set up the development environment (see the [contributor guide](docs/en/contributing.md)).
3. Make your changes. Keep commits atomic and follow
   [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `chore:`, `refactor:`,
   `test:`…).
4. Before opening the pull request, check locally:

   ```text
   npm run lint
   npm run format:check
   npm run typecheck
   npm run test
   npm run build
   ```

   If you changed the documentation, also run `npm run lint:md` and `npm run docs:check`.

5. Open the pull request with a clear description of what changes and why, then wait for continuous integration to be
   green: the pull request cannot be merged before.

## Code style

- Strict TypeScript, no `any`.
- No hardcoded user-visible text — everything goes through next-intl (`messages/fr.json` and `messages/en.json`).
- No npm script that depends on a specific Unix or Windows shell (see docs/architecture.md).
- The `src/components/ui/` components are generated by shadcn/ui: do not edit them by hand.

## Documentation

The documentation is written in English and in French, with the same pages in `docs/en/` and `docs/fr/`: a change to
one is a change to the other. See the "Documentation" section of the [contributor guide](docs/en/contributing.md).

## Questions

Open a GitHub issue or discussion. For more direct contact (a question before getting started, a report that falls
under the [Code of Conduct](CODE_OF_CONDUCT.md)), the project's maintainer can be reached on Discord: `meteore_1`. A
security flaw is **not** reported in public: see [SECURITY.md](SECURITY.md).
